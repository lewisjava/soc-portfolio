# Slingshot
Slingway Inc., a leading toy company, has recently detected suspicious activity on its e-commerce web server and potential unauthorized modifications to its database. To investigate the incident, you have been brought in to analyze the available logs and determine the scope and impact of the attack. To aid in your investigation, you've been provided with access to an Elastic Stack instance containing logs from the suspected compromise. Below are the credentials required to access the Kibana dashboard. Slingway's IT team noted that the suspicious activity began on July 26, 2023.


Objectives

By investigating and answering the questions in the next task, you will build a timeline of events to support the incident response process and deliver clear, evidence-based findings. In your investigation, you seek to answer the following questions.

1. What reconnaissance and enumeration techniques were used?
2. What vulnerabilities were exploited on the web server?
3. How did the attacker gain administrative access?
4. What sensitive data was accessed or exfiltrated?

## The slingshot investigation
**What is the attacekrs IP address?**
My first step was to look in the logs for any 404 errors since the attacker was enumarating the web server it is very likely they will have run into pages that did not exist. Doing this gave me the attackers ip, 10.0.2.15, the user agent which shows they are using Gobuster, as well as the transaction ID/transaction remote address I can use to track everything from this attacker and will be used to pivot from.
![slingshot1](/static/images/slingshot1.png)

**What is the first scanner that the attacker ran against the web server**
Searching for events using the attackers transaction remote address and sorting the events by old-new I can see the first scanner the attacker used was Nmap scripting engine.
![slingshot2](/static/images/slingshot2.png)

**What is the user agent of the directory enumeration tool that the attacker used on the web server**
Looking through the logs I can see that the attacker used Gobuster to enumerate the web server
![slingshot3](/static/images/slingshot3.png)

**In total, how many 404 responses did the attacker receive when enumerating the web server** 
Filtering for the attackers ip and response status 404 returns 1867 404 responses.
![slingshot4](/static/images/slingshot4.png)

**What flag was discovered in one of the directories identified during enumeration**
After filtering for 200 respons status with the attackers ID, I searched for any sign of *flag* in the http.url which gave me the flag the attacker found.
![slingshot](/statue/images/slingshot5.png)

**What login page did the attacker discover using the directorye enumeration tool**
scrolling through the 203 200 responses generated by the attacker I can see the successfull enumerations made, where the attacker enumerates a directory called admin-long.php
![slingshot6](/static/images/slingshot6.png)

**What is the user-agent of the brute-force tool that the attacker used on the admin panel** 
This can be seen in the previous screenshot where the attacker uses Mozilla/4.0 (Hydra) a popular brute force tool.

**What username:password combination did the attacker use to gain access to the admin page**
Looking in the successfull Hydra response, inside the message field there is a base64 string after the authorization field, taking this into cyberchef shows the username and password they got.
![slingshot7](/static/images/slingshot7.png)
![slingshot8](/static/images/slingshot8.png)

**What flag was included in the file that the attacker uploaded to the /admin/upload.php directory**
Filtering for POST requests returns only 40 results where I can find a post request made to this directory, where I can see the flag inside the request body.
![slingshot9](/static/images/slingshot9.png)

**What was the first command the attacker ran using the web shell**
Looking at the web shell commands ran it can be seen the first one ran is whoami
![slingshot10](/static/images/slingshot10.png)

**Which file was accessed via Local File Inclusion to retrieve database credentials**
Local file inclusion is a web security flaw that occurs when a web app uses raw user input to load files, since this is identified by attackers typing "../../" seqeuences to escape the web folder it is easy to find. After finding this input I can see the attacker gains access to the config-db.php file.
![slingshot11](/static/images/slingshot11.png)

**What is the name of the database the attacker exported via /phpmyadmin**
Continuing through the attackers chain I can see the attacker exported a db called customer\_credit\_cards
![slingshot12](/static/images/slingshot12.png)

**What flag does the attacker insert into the database using import.php**
After filtering for import.php with the attackers IP, two events appear with one containing URL encoding, after taking this to cyberchef to decode I get the flag.
